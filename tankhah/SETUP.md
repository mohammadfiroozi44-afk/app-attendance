# راه‌اندازی تنخواه‌یار

این برنامه کاملاً مستقل از سایت تردد‌یار است: شیت گوگل جدا، پروژه‌ی Apps Script جدا، آدرس Web App جدا،
و لیست کاربران/ورود جدا. هیچ فایلی از تردد‌یار تغییر نکرده و هیچ داده‌ای بین این دو به اشتراک گذاشته نمی‌شود.

## ۱) ساخت شیت گوگل و پروژه‌ی Apps Script

1. یک Google Sheet جدید و خالی بسازید (مثلاً با نام «داده‌های تنخواه‌یار»).
2. از منوی بالا: `Extensions` (پسوندها) → `Apps Script`.
3. محتوای فایل `Code.gs` این پوشه را کپی کنید و در ویرایشگر Apps Script (روی فایل پیش‌فرض `Code.gs`) جایگزین کنید.
4. از منوی سمت چپ Apps Script، وارد `Project Settings` (تنظیمات پروژه) شوید و در بخش `Script Properties`
   یک مقدار جدید اضافه کنید:
   - نام: `SETUP_KEY`
   - مقدار: یک رمز دلخواه و قوی (فقط برای یک‌بار استفاده در ساخت اولین مدیر — بعداً می‌توانید حذفش کنید)

## ۲) دیپلوی به‌عنوان Web App

1. در Apps Script: `Deploy` → `New deployment`.
2. نوع (Select type) را روی `Web app` بگذارید.
3. تنظیمات:
   - `Execute as`: **Me** (خودتان)
   - `Who has access`: **Anyone** (چون فرانت‌اند بدون لاگین گوگل به آن وصل می‌شود؛ امنیت با توکن و رمز عبور داخل خود برنامه تأمین می‌شود)
4. `Deploy` را بزنید و مجوزهای درخواستی گوگل را تأیید کنید.
5. آدرس Web App (چیزی شبیه `https://script.google.com/macros/s/AKfycb.../exec`) را کپی کنید.

> هر بار که کد `Code.gs` را تغییر دادید، باید از `Deploy` → `Manage deployments` → مداد کنار دیپلوی فعال →
> `New version` → `Deploy` را بزنید تا نسخه‌ی جدید واقعاً منتشر شود.

## ۳) وصل‌کردن فرانت‌اند به بک‌اند

فایل `tankhah/index.html` را باز کنید، خط زیر را پیدا کنید:

```js
const API_URL = "PASTE_YOUR_TANKHAH_APPS_SCRIPT_WEB_APP_URL_HERE";
```

و آدرس Web App مرحله‌ی قبل را جای آن بگذارید. سپس تغییرات را کامیت/پوش کنید.

## ۴) ساخت اولین مدیر

1. برنامه را باز کنید (مثلاً `https://<username>.github.io/<repo>/tankhah/`).
2. روی «راه‌اندازی اولیه (ساخت مدیر)» بزنید.
3. کلید راه‌اندازی همان `SETUP_KEY` است که در مرحله‌ی ۱ تنظیم کردید.
4. نام، نام‌کاربری و رمز عبور مدیر را وارد کنید و ثبت کنید.
5. بعد از ساخت مدیر، برای امنیت بیشتر می‌توانید `SETUP_KEY` را از Script Properties حذف کنید
   (چون این عملیات فقط یک‌بار — وقتی هیچ کارمندی وجود ندارد — قابل استفاده است، دیگر لازم نیست).

از این پس با همان نام‌کاربری/رمز عبور مدیر وارد شوید و بقیه‌ی کارمندها را از داخل برنامه
(تب «کارمندها») اضافه کنید.

## به‌روزرسانی Code.gs (اگه قبلاً یک بار دیپلوی کردی)

اگه `Code.gs` رو دوباره جایگزین کردی (مثلاً برای اضافه‌شدن شماره سند / وضعیت رسید / عکس رسید):

1. کد جدید رو در ویرایشگر Apps Script جایگزین کن و Save کن.
2. `Deploy` → `Manage deployments` → روی مداد ✏️ کنار دیپلوی فعال بزن → `Version: New version` → `Deploy`.
   **این کار آدرس Web App رو عوض نمی‌کنه** (همون `API_URL` قبلی توی `index.html` معتبر می‌مونه)، پس نیازی به تغییر چیزی توی فرانت‌اند نیست.
3. چون این نسخه از کد اولین باری‌ه که به Google Drive دسترسی می‌خواد (برای ذخیره‌ی عکس رسیدها)، گوگل یک بار دیگه صفحه‌ی درخواست مجوز نشون می‌ده — تاییدش کن.

## عکس رسید و Google Drive

- وقتی کسی برای یک «خرج» عکس رسید آپلود می‌کنه، عکس داخل یک پوشه‌ی جدید به اسم «تنخواه‌یار - رسیدها» در Google Drive همون حسابی که Apps Script رو دیپلوی کرده ذخیره می‌شه.
- برای اینکه عکس بدون نیاز به لاگین گوگل توی برنامه نمایش داده بشه، لینک هر عکس روی «هرکسی که لینک رو داشته باشه» تنظیم می‌شه — یعنی این لینک رمزگذاری‌شده نیست، هرکسی که لینکش رو داشته باشه می‌تونه عکس رو ببینه (مثل بقیه‌ی بخش‌های این ابزار، برای استفاده‌ی داخلی طراحی شده، نه برای داده‌ی خیلی محرمانه).

## نکات

- تمام کلیدهای ذخیره‌شده در مرورگر (localStorage) با پیشوند `tankhah_` هستند و کاملاً از
  کلیدهای تردد‌یار (که پیشوند ندارند) جدا هستند.
- Service worker این برنامه با scope محدود به `./tankhah/` ثبت می‌شود و کاری به service worker
  ریشه‌ی سایت (تردد‌یار) ندارد.
- رمزهای عبور هرگز به‌صورت متن ساده به سرور فرستاده نمی‌شوند؛ در مرورگر با SHA-256 هش می‌شوند.
- انواع تراکنش:
  - **دریافتی**: صندوق شرکت → کارمند (فقط مدیر ثبت می‌کند)
  - **پرداختی**: کارمند → صندوق شرکت، مثلاً برگشت تنخواه اضافه (فقط مدیر ثبت می‌کند)
  - **انتقال**: کارمند → کارمند دیگر (خود کارمند یا مدیر می‌تواند ثبت کند)
  - **خرج**: از موجودی تنخواه کارمند کم می‌شود، با دسته‌بندی و توضیحات (خود کارمند یا مدیر می‌تواند ثبت کند)
- برای ابطال یک تراکنش اشتباه، آن را حذف نکنید — از دکمه‌ی «ابطال» در تب تراکنش‌های مدیر استفاده کنید؛
  تراکنش باطل‌شده برای حفظ سابقه در تاریخچه با خط‌خورده باقی می‌ماند و در محاسبه‌ی موجودی لحاظ نمی‌شود.
- هر تراکنش یک **شماره سند** خودکار و پیوسته می‌گیرد (شبیه فایل اکسل قبلی) — برای پیگیری راحت‌تر.
- برای «خرج» و «پرداختی» می‌توان **طرف‌حساب** (اینکه پول عملاً بابت چه کسی/کجا بود) را جدا از فردی که از تنخواهش کم می‌شود وارد کرد؛ خالی گذاشتنش یعنی خودِ همان فرد.
- هر «خرج» یک **وضعیت رسید** دارد (رسید نشده / رسید شده) که به‌طور پیش‌فرض «رسید نشده» است؛ مدیر از تب تراکنش‌ها با کلیک روی همین برچسب می‌تواند وقتی فیش کاغذی رسید، وضعیتش را به «رسید شده» تغییر دهد.
- می‌توان هنگام ثبت «خرج»، عکس رسید را از گوشی/دوربین آپلود کرد؛ عکس قبل از ارسال در همان مرورگر کوچک‌تر می‌شود تا حجمش پایین بماند.
